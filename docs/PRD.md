# PRD: 팀 편성 웹 앱

## 목표
가상 학생이 팀 프로젝트 팀을 스스로 꾸리고, 남은 학생은 AI가 배정하며, 앱이 AI의 답을 규칙으로 검사한다.

## 사용자
- 학생: 학번과 비밀번호로 로그인해 팀을 보고, 지원하고, 내 팀의 지원에 투표한다.
- 관리자(학번 `admin`): 명단을 올리고, 모집을 마감하고, 배정안을 받아 확정한다.

## 범위
| 기능 | 요구사항 |
|---|---|
| 명단 | BOM이 있는 UTF-8 CSV와 팀 수로 앱 상태를 초기화한다. 관리자 계정은 남긴다. |
| 로그인 | 비밀번호는 bcrypt 해시로 저장한다. 구글 로그인은 쓰지 않는다. |
| 지원 | 빈 팀은 바로 승인. 팀원이 있으면 대기. 팀 꽉 참, 주 역할 중복, 이미 팀 있음, 대기 중, 마감, 필수 역할 자리 부족은 막는다. |
| 투표 | 투표하는 때의 팀원 전원 찬성이면 승인 직전 검사 후 승인. 한 명이라도 거부하면 바로 거절. 한 번 투표하면 못 바꾼다. |
| 마감 | 대기 지원은 거절하고, 1명뿐인 팀의 학생은 뺀다. |
| 배정 | 1~3차 모델을 차례로 쓴다. 다섯 가지 검사를 통과한 배정안만 보여 준다. 3차까지 실패하면 앱이 직접 찾는다. 배정이 없으면 이유를 보여 준다. |
| 갱신 | 다른 사람의 변경이 5초 안에 화면에 나타난다. |

## 팀 규칙
- 모든 팀은 2~4명이며 빈 팀이 없다.
- 한 팀에 주 역할이 겹치지 않는다.
- 모든 팀에 기획자와 웹 프로그래머를 맡을 학생이 서로 다른 사람으로 있다. 주 역할이나 보조 역할 어느 쪽이든 된다.
- 지원 시 남는 자리 수가 아직 못 채운 필수 포함 역할 수보다 적으면 막는다.

## 제약
- 배포: Streamlit Community Cloud. DB: Supabase, 테이블 이름은 `tf_`로 시작한다.
- 화면 요소의 `key`는 공고 2.7절 표를 그대로 쓴다.
- `result`는 승인, 대기, 거절, 막힘 가운데 하나로 시작한다.
- 키, DB 주소, 관리자 비밀번호는 `.env`와 Streamlit Secrets에만 둔다.
- 실제 사람의 이름과 학번을 쓰지 않는다.

## 범위 밖
- 학생의 역할 변경, 투표 변경, 확정 뒤 팀 수정, 구글 로그인

## 완료 기준
- 공고 부록의 연습용 시나리오 3개가 기대 결과대로 끝난다.
- AI가 모두 실패해도 규칙을 지키는 팀 구성이 확정된다.
- 배포 주소를 로그인하지 않은 브라우저로 열 수 있다.
