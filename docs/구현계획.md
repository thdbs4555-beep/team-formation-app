# 구현 계획

## 구조
| 파일 | 역할 |
|---|---|
| `teamapp/rules.py` | 팀 규칙, 배정안 검사, 전수 탐색. DB와 화면에 의존하지 않는다. |
| `teamapp/service.py` | 지원, 투표, 마감, 배정, 확정. 첫 단어가 승인/대기/거절/막힘인 안내를 돌려준다. |
| `teamapp/ai.py` | 오픈라우터 호출과 모델당 120초 전체 제한 |
| `teamapp/db.py` | Postgres 연결 풀. 시험용 SQLite도 같은 SQL로 쓴다. |
| `streamlit_app.py` | 화면. `key`는 공고 2.7절을 따른다. |
| `schema.sql` | 테이블과 유일성 제약 |
| `tests/test_scenarios.py` | 부록 시나리오와 규칙 시험 |

## 주요 결정
- 규칙을 순수 함수로 분리해 부록 시나리오를 Supabase 없이 시험한다.
- `join_problem`을 지원 때와 승인 직전에 함께 쓴다. 그래서 두 검사의 기준이 같다.
- 쓰기는 `pg_advisory_xact_lock`으로 한 번에 하나씩 처리하고, 마지막 방어선으로 `tf_members`의 유일성 제약을 둔다.
- AI 배정은 배경 스레드에서 돌리고 진행 상황을 `tf_settings`에 적는다. 화면은 5초 자동 갱신으로 이를 읽으므로, 응답을 기다려도 화면이 멈추지 않는다.
- 모델 호출은 별도 스레드에서 돌리고 120초가 지나면 기다리지 않는다. `requests`의 timeout은 전체 시간을 재지 못하기 때문이다.
- AI를 부르기 전에 전수 탐색을 먼저 돌린다. 배정이 없으면 AI를 부르지 않고 이유를 보여 주고, 무료 호출 횟수도 아낀다.
