## 3. 고른 해결 방법
| 기능 | 고른 해결 | 구현 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결 | `st.fragment`로 5초마다 갱신 |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 | 지원 단계에서 자리가 모자라게 되는 지원을 막음 |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 | 승인 직전에 규칙을 다시 검사함 |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결 | `tf_members`의 유일성 제약 |
| AI 응답이 늦을 때 | 어려운 해결 | 모델마다 120초 전체 대기 시간을 재서 끊음 |
| 3차 모델까지 실패 | 어려운 해결 | 다섯 가지 검사를 통과하는 배정을 전수 탐색함 |
| AI 대기 중 화면 | 어려운 해결 | 몇 차 모델의 응답을 기다리는지 보여 줌 |
| DB 일시정지 막기 | 어려운 해결 | GitHub Actions 예약 작업으로 매일 DB에 질의함 |

## 4. 쓴 모델 3개
- 1차 `cohere/north-mini-code:free`
- 2차 `nvidia/nemotron-3.5-lightning:free`
- 3차 `google/gemma-4-31b-it:free`

## 5. 오픈라우터 AI 모델 호출 실패 사례
모델 후보를 고르려고 `scripts/try_models.py`로 실제 호출했을 때 다음과 같이 실패함(터미널 출력).

```
1차 nvidia/nemotron-3-ultra-550b-a55b:free: 호출 실패 (120초 안에 응답이 끝나지 않음) 120.0초
2차 google/gemma-4-31b-it:free: 호출 실패 (HTTP 429) 0.6초
```

같은 시험에서 `nvidia/nemotron-3.5-lightning:free`는 68.2초 만에 빈 응답을 냈음. 앱은 세 경우를 모두 실패로 처리하고 다음 모델로 넘어가게 만듦. 이 시험 결과에 따라 배정안을 낸 `cohere/north-mini-code:free`를 1차로 정함. 그 모델이 성공한 화면: `img/ai-success.png`

## 6. 클로드의 잘못된 추론이나 답변
- 잘못된 내용: 클로드가 만든 정리 스크립트가 빈 폴더 삭제에 권한 오류로 실패했는데도 "REMOVED"를 출력함. `Remove-Item`의 실패가 스크립트를 멈추지 않아서, 삭제 성공을 확인하지 않고 다음 줄의 문구가 찍힘.
- 알아챈 방법: 출력에 권한 오류가 함께 있어 폴더 존재 여부를 다시 확인했고(`Test-Path` 결과 True), 폴더가 남아 있음을 확인함. 출력 문구만 믿지 않고 실제 상태를 다시 확인해야 함을 배움.

## 7. 제출한 앱의 문제점이나 개선 필요 사항
- 문제: 지원이 거절되어도 지원자는 그 사실을 알 수 없음. 거절 안내는 거부 단추를 누른 팀원의 화면에만 나오고, 지원자가 다시 로그인하면 안내 없이 "아직 팀이 없음"만 보임. 지원자는 왜 지원 단추가 다시 눌리는지 알 수 없음.
- 발견한 단계: 부록 1(쉬움) 4단계. 학생4가 학생7의 지원을 거부한 뒤 학생7로 로그인해 확인함.
- 화면: `img/step4-no-reject-notice.png`
- 개선 방향: 학생 화면에 자기 지원의 마지막 결과와 거절 이유를 보여 줌.

## 로컬 실행
`.env.example`을 `.env`로 복사해 값을 넣고 실행한다.

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```

시험은 Supabase 없이 돌아간다.

```bash
pytest tests
```
